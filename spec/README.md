# 规格索引与 Agent 阅读路由

本目录采用渐进式披露。Agent 不得默认读取全部规格。

## 最小阅读规则

1. 所有任务先读取根目录 AGENTS.md。
2. 所有产品或实现任务再读取：
   - spec-design-basketball-tactical-spatial-simulator.md
3. 根据当前任务，只加载下表中直接相关的专项规格。
4. 若任务跨越多个层，再加载受影响的其他文件。
5. 不要为了“可能有用”读取全部规格。

## 按任务选择文件

| 当前任务 | 必须读取 | 通常不需要 |
| --- | --- | --- |
| 讨论产品方向、范围、是否该做 | 产品意图与边界 | 其他全部 |
| 设计模拟循环、空间计算、动作、策略、重放 | 产品意图与边界 + 运行时决策架构 | AI 规格 |
| 修改世界状态、战术 DSL、事件或序列化 | 产品意图与边界 + 数据契约 | AI 规格、验证规格 |
| 开发自然语言战术、模型策略或 AI 解释 | 产品意图与边界 + AI 规格；涉及输出字段时再读数据契约 | 运行时细节，除非改变策略接口 |
| 编写测试、黄金场景、验收或评审 | 产品意图与边界 + 验证规格 + 被测模块规格 | 无关专项规格 |
| 开发 Web 圆点展示 | 产品意图与边界 + 数据契约；会改变模拟时再读架构 | AI 规格 |
| 进行跨层架构修改 | 产品意图与边界 + 所有受影响专项规格 | 未受影响规格 |

  - 明确非目标；
  - 不可破坏的产品原则。

## 信息唯一归属

为避免重复和漂移，同一事实只能有一个权威归属：

| 信息 | 权威文件 |
| --- | --- |
| 产品是什么、做什么、不做什么 | 产品意图与边界 |
| 运行时行为与模块关系 | 运行时决策架构 |
| 字段名、结构、版本 | 战术与模拟数据契约 |
| AI 权限、上下文和失败处理 | AI 原生集成边界 |
| 验收、测试和质量门禁 | 验证与评估流程 |

其他文件只能链接到权威文件，不应复制完整规则。

## 上下文预算原则

- AGENTS.md 只保留高风险工作规则和阅读路由。
- Level 1 文件只保留每个任务都需要的产品边界。
- Level 2 文件按单一关注点组织。
- 大型 JSON 示例只放在数据契约。
- 测试矩阵和验收列表只放在验证规格。
- 外部参考资料只在确实影响决策的规格中保留。
- 实现代码中的局部说明应靠近代码，不回填到产品规格。

若某专项规格持续增长，应优先按稳定职责继续拆分，而不是删掉必要约束。拆分前必须确认新文件具有独立的阅读触发条件，否则过度拆分只会增加导航成本。
