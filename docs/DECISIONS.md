# 关键决策与原因索引

这不是每日开发日志，也不复制测试细节。它保存会影响后续 agent 判断的稳定决定：做什么、不做什么、为什么，以及证据在哪里。

状态含义：

- **生效**：当前仍约束实现。
- **完成**：决定已经形成封存检查点，回归仍需保护。
- **延期**：明确没有完成，不得误写为已有能力。
- **被后续决定细化**：原方向保留，但当前执行口径见更新决定。

## D001：三层架构与信息所有权

**决定：** 进攻和防守各自以队级规划器统一分配两名球员角色；中立世界只解析双方已提交的运动意图和真实事件。

**原因：** 如果球员各自逐帧贪心，会出现队内职责冲突；如果中立解析器替球队挑方案，计划与结果就无法区分；如果一队读取对方隐藏计划，策略对局失去意义。

**后果：** UI 可以作为全知观察者，但 planner observation 必须按队伍裁剪。任何新增原语都要明确候选、角色所有权、公开可行性和世界成立事件。

**证据：** `lib/pnr-core.ts` 的 observation、plan 和 step 流程；进度账本第 2 节；P00 信息边界测试。

## D002：固定步世界与有限重规划

**决定：** 世界以 `1/60s` 推进；计划只在事件可消费、终止条件或有限看门狗到达时重算，计划具有最短承诺和滞回。

**原因：** 预录轨迹无法泛化，逐帧重新选方案又会抖动。固定步和离散决策边界让连续画面、确定性重放和因果审计同时成立。

**后果：** 计划事件不能同 tick 立即产生后续选择；测试要分别记录事件发生 tick 与可消费 tick。

**证据：** `FIXED_DT`、planning log、event `availableAtTick` 与确定性测试。

## D003：掩护事实必须分层

**决定：** `contact`、`route_exposure`、`impeded`、`screen_effective` 独立解析。

**原因：** “O5 想设掩护”不等于 D1 已受影响；单纯距离接近也不等于进入合理移动走廊。分层事实可以明确回答为什么某次掩护有效或无效。

**后果：** Formation 阶段即使 O5 到 anchor，也不能提前产生 `screen_effective`；无局部接触且无 route exposure 时不得出现 impeded。

**证据：** `evaluateScreenFacts`、S/G 核心不变量与 F00 负向门。

## D004：S/G/P 是不同证据层，不是场景编号竞赛

**决定：** S 场景证明一个可观看因果证人；G 验证现有原语在连续、组合、镜像和 held-out 输入下的稳定性；P 只表达教练对合法候选的偏好。

**原因：** 现实的几十种回合往往是少量原语在不同数值和顺序下组合。继续堆孤立场景既不能证明泛化，也容易退化成 case patch。

**后果：** 新需求先分类为数值变化、已知原语组合、策略偏好、新原语或新项目范围，再决定验证方式。

**证据：** [战术覆盖与泛化模型](./2026-08-07-tactical-coverage-and-generalization-model.md)，以及进度账本第 5–8 节。

## D005：真实左右镜像

**决定：** 规划器内部只维护右侧规范战术坐标，映射回真实 right/left 世界后由同一个中立解析器运行。

**原因：** 复制左右算法会让阈值、角色和事件逐渐分叉；仅镜像 Canvas 又不能证明左侧世界真实合法。

**后果：** 不允许 left planner、side 专用常数或结果补丁。镜像审计比较位置、速度、球、候选、计划、角色、事件和终局。

**证据：** G07 行为提交 `d92ed9f`；G08 与 P03 左右审计。

## D006：Policy 只能影响合法候选优先级

**决定：** 评分顺序固定为硬可行性 → `baseScore` → 本队 `strategyAdjustment` → `effectiveScore`；默认策略 adjustment 为 0。

**原因：** 如果策略能恢复 veto 候选、修改几何或直接指定结果，策略名称就会伪装尚未实现的篮球原语。

**后果：** 进攻只能读进攻策略，防守只能读防守策略，中立世界不接收策略。真正沉退、追过、ICE 或夹击必须先作为新原语实现。

**证据：** P00 `31aad3c`、P01 `6f9e60a`、P02–P03 `30e218b`。

## D007：P04 明确跳过

**决定：** 不执行完整 `2 × 3` 策略组合的新 held-out 起手。

**原因：** 用户判断 P00–P03 已达到当轮可观看闭环，继续扩展的收益不足以突破停止纪律。

**后果：** 可以声称有限策略矩阵在批准输入上成立；不能声称所有六组已经通过全新的策略 held-out 起手。后续只有重新批准才能开启。

**证据：** Policy 收口提交 `c4ada7d` 与进度账本阶段 C–D。

## D008：Formation 是 opt-in 前置阶段

**决定：** `form_pnr` 在旧挡拆阅读之前增加形成阶段；缺省 `preset_pnr` 保持原行为。

**原因：** G/P 的起手已经接近形成掩护。让球员从偏移位置自行形成需要新的角色、地标、运动与交接事件，不能假装是原有参数泛化。

**后果：** Formation 只能在显式输入下运行；旧 170 输入、G08 manifest 和 P 策略必须零行为变化。

**证据：** 进度账本阶段 E；稳定基线 `c4ada7d`。

## D009：F00 先固定起手，再讨论随机位置

**决定：** F00 只使用一个批准的合法偏移起手与真实左右镜像，暂不允许任意 offsets、自动选边、随机或拖拽。

**原因：** 首先需要回答的是四人能否连续形成掩护、保持原责任并安全接入旧内核。扩大起手会同时引入阵型识别、选边、路线规划和不可行局面，无法判断失败属于哪一层。

**后果：** F01 才可能验证少量结构化起手，F02 才可能引入有界 seed 随机；二者都尚未批准。

**证据：** 进度账本 F00 路线与 `bb138dc`。

## D010：视觉验收不替代负向语义门

**决定：** 保留 F00 标准动画的人眼通过结论，但在提交前修复联合就绪、D1 篮筐侧、语义 PASS、输入拓扑和信息所有权。

**原因：** 标准样例未暴露三个客观反例：D1 交接位置不在真正篮筐侧；O5 到位可在 O1 尚未就绪时触发进入 PnR；不合理 gate 拓扑可被接受。人眼没有机会看到未暴露输入，不能替代负向检查。

**后果：** 不要求保留固定 tick、USE/SWITCH 或终局；修复站位后只要求结果仍然合法、确定且可解释。纠偏后只复验设稳和 next-tick 交接两个瞬间。

**证据：** `bb138dc`、进度账本“F00 独立审计后的提交前纠偏门”、`docs/CURRENT.md`。

## D011：小增量与版本纪律

**决定：** 每轮只实现一个可观看问题；自动门通过后由用户人眼判断，成功后独立 commit/push，失败则保留最小反例并停止扩展。

**原因：** 这让每个篮球语义都有明确证据和回退点，也避免新 UI、策略、参数与算法修复混成不可审计提交。

**后果：** 未获得用户确认前不扩大下一编号；不改写已推送历史；混合工作树只暂存明确属于当前任务的文件。

**证据：** S/G/P 已有原子提交链和当前 Formation 分支纪律。

## 何时追加新决策

只有以下变化需要新增决策：

- 批准或拒绝一个新阶段、新篮球原语或新人数范围；
- 改变三层架构、信息所有权或中立世界职责；
- 改变泛化、策略或 held-out 的验收方法；
- 改变当前停止点或版本纪律；
- 用新的证据推翻或细化已有重要判断。

普通重命名、阈值实现细节、测试补充和 UI 文案不需要新决策。若旧决定被替代，保留原条目并新增一条说明替代原因，不要擦除历史。
