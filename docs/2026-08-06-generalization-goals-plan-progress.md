## 1. 重新确认后的总体目标

本项目最终希望得到的，不只是几个可以播放的固定 2v2 场景，而是一个独立、确定性、可观看、可解释，能够接受有限“教练策略”配置，并逐步从合理偏移起手自行形成挡拆的 2v2 算法实验台。

总体目标分为五层：

1. **篮球内核正确。** O5 在 O1 一侧建立掩护关系，O1 能根据公开防守状态使用或拒绝掩护；D1、D5 必须作为防守队协调响应。
2. **在限定输入域内具备泛化。** 同一套算法能够处理连续速度、反应时间和合理位置变化，而不是为每个场景写一套答案。
3. **能够从合理起手形成挡拆。** 在旧挡拆解析内核之前增加明确的形成阶段，让 O1 等待、O5 到位设掩护、D1/D5 保持原责任。`screen_set` 只证明 O5 已经设稳；只有 O1 与 O5 联合就绪后，才能在下一合法决策边界接通后续阅读。
4. **支持队级策略配置。** 在泛化基础基本成立后，允许在回合开始前分别选择进攻和防守的整体策略。策略类似教练布置的原则、阶段优先级和回退顺序，而不是逐帧遥控两名球员。
5. **所有变化都可观察、可解释、可复现。** 用户能看到双方策略、当前队级计划、两名球员的角色、候选方案、否决原因和关键世界事件，并用相同输入稳定重放。

Policy 检查点已经完成第一层理想演示：选择一个处于批准输入域内的 2v2 起手和双方策略，点击运行后配置锁定，两支队伍按照各自策略与公开世界自动对局。Formation 阶段开始补第二层能力：从尚未站成掩护的合理起手出发，由双方队级计划先形成站位，再无缝接入同一个挡拆内核。相同输入与策略仍必须完全复现，不能因为增加形成阶段而改写已经批准的 S/G/P 行为。

用户已经批准并完成 `F → A → T → I → V` 逐层收敛；Formation F00–F03、Autonomous Setup A00–A01、T00–T01、I00–I03 与 V00–V03 均已封存。A 仍只在 F01/F02/F03 已证明的合法形成域工作；独立 T 也只证明显式冻结 preset 输入，I02 只把封存 P03 策略接入锁定 A01 集成域，V 也只验证锁定 bounded integrated held-out，不等于完全无结构的半场任意摆放。拖拽编辑、手动控制、ML/RL、5v5、完整比赛、投篮结果、犯规、转换进攻、旧项目迁移和生产级 UI 仍不在当前路线内。

## 2. 不可破坏的架构与篮球边界

- 架构继续保持为进攻队级规划器、防守队级规划器、中立世界与运动解析器。
- 进攻和防守规划器只读取公开世界事实、自队职责和自队策略，不能读取对方隐藏计划或隐藏策略。`explicit` Formation 中调用方提供的掩护侧与公共形成区域可以被双方读取；`auto` 中规划器选定的 side/anchor、O1 等待点和 use/reject gate 属于进攻私有计划，只有真实运动形成稳定几何承诺并发布公开事件后，防守才能在下一规划边界消费。UI 可以从用户观察者视角展示双方信息，但不能把这种全知显示对象回传给球队规划器。
- 中立解析器只执行固定步长运动、局部身体几何、边界、球权、传球飞行、实际第一触球和事件归属；不能替任一球队评分或选择方案。
- 世界按固定 `1/60s` 时间步连续推进；重规划只由事件、终止条件或有限看门狗触发，并保留最短承诺与滞回。
- `contact`、`route_exposure`、`impeded`、`screen_effective` 必须分别成立；没有局部接触或合理移动走廊时不得产生远程阻挡。
- 硬可行性约束始终高于评分偏好和教练策略。任何策略都不能强迫球员瞬移、远程挡人、穿越身体或完成不存在的传球窗口。
- 计划意图不能直接变成世界结果。即使规划器决定绕前、协防或分球，也必须等运动和局部几何在中立世界中真实成立。
- 相同初始世界、相同随机种子和相同双方策略必须逐 tick 复现。

## 3. 当前算法是什么

现有运动不是逐帧手写轨迹，也不是预录动画。当前内核采用：

1. 少量显式、可解释的队级候选方案和球员角色。
2. 规划器读取公开位置、速度、球权与已解析事件。
3. 硬可行性约束和确定性短推演比较候选方案。
4. 选中的队级计划统一分配两名球员的职责和运动目标。
5. 中立解析器逐 tick 处理加速受限运动、局部身体几何、球权、传球飞行与实际第一触球。
6. 世界事件到达下一合法决策边界后，双方才分别重新规划。

因此当前属于“人工定义篮球战术语法，算法根据公开世界实时选择方案和解析运动”。Policy 检查点已经证明预设挡拆起手下的局部计算与队级策略能力；Formation 阶段将以显式 opt-in 模式逐步解除“掩护关系已经接近成形”的起手假设。F00 仍只是一个固定偏移证人，不能称为全局空间泛化。

## 4. 已完成的队级教练策略能力

### 4.1 策略与当前队级计划不是一回事

队级策略是回合开始前配置的长期原则；队级计划是规划器在某一个决策时刻，根据策略、公开世界和硬可行性选出的当前行动。

```text
赛前进攻/防守策略
        ↓
各自队级规划器读取公开世界并比较合法候选
        ↓
当前队级计划为两名球员分配协调角色
        ↓
中立解析器执行真实运动、传球和事件
```

策略不能包含固定轨迹、预设胜负、指定接球者或“本场景必须选某方案”等答案。它只能影响合法候选之间的优先级、风险倾向、允许范围和回退顺序。

### 4.2 策略应按决策阶段表达

进攻和防守的候选并不都处于同一个决策阶段，因此不能简单做成一张不分语境的总排行榜。暂定按阶段组织优先级。

进攻策略可能包含：

- 初始阅读：使用掩护与拒绝掩护的倾向。
- 换防以后：`ATTACK_BIG`、`FEED_SEAL`、`RESET_MISMATCH` 的优先关系。
- O5 接球以后：`POST_FINISH`、等待协防、`KICK_OUT` 的风险与收益倾向。
- 整体偏好：保持球权、制造篮下压力、优先攻击错位或优先寻找顺下。

防守策略可能包含：

- 挡拆覆盖：换防、绕下、追过或沉退等覆盖方式的优先级与适用条件。
- 换防后卡位：`FRONT_SEAL` 与 `BACKSIDE_CONTEST` 的优先关系。
- O5 接球以后：`STAY_HOME_POST` 与 `DIG_POST` 的帮助原则。
- 整体偏好：保护篮下、限制持球人、减少换防或减少离开射手。

这些名字只是目标方向，不代表所有原语已经存在。策略层不能凭一个按钮制造尚未实现的篮球行为。例如，如果真正的沉退防守尚未作为通用候选实现，就必须先用独立小增量实现、验证并由用户亲眼确认，之后才能加入“沉退优先”策略。

### 4.3 策略的优先级不能越过合法性

正确顺序必须是：

1. 中立世界提供公开事实。
2. 队级规划器先执行硬可行性检查。
3. 在可行候选中，策略影响优先级、评分偏置或回退顺序。
4. 规划器产生当前队级计划和两名球员角色。
5. 中立解析器执行并决定真实世界结果。

例如选择“绕前优先”时，如果 D1 的合法绕前 ETA 已经晚于传球到达时间，规划器仍必须否决绕前并执行后备方案。选择“积极协防”也不能让 O5 在 D5 尚未真实靠近时提前分球。

### 4.4 策略生命周期与信息边界

- 进攻和防守策略都在回合开始前选择。
- 点击运行后，两套策略锁定；需要重置回合才能修改。
- 进攻规划器只能读取进攻策略，防守规划器只能读取防守策略。
- 对手只能通过已经发生的移动、角色和事件推断倾向，不能直接读取隐藏策略名称或优先级。
- 中立解析器不读取策略偏好，只接收双方已经提交的运动意图。
- 当前界面应显示自用户视角下的双方策略、优先级和否决原因，但显示层不能反向修改模拟状态。

### 4.5 策略能力的最低验收标准

- 相同世界和相同策略组合逐 tick 完全复现。
- 相同世界在不同策略组合下，允许形成不同但合法、可解释的队级计划。
- 首选策略不可行时，能稳定落入明确的第二选择或安全退出，而不是卡死或逐帧改主意。
- 两名队友始终由一个队级计划统一分工，不能出现角色所有权冲突。
- 策略不能进入对手观察对象，也不能进入中立结果判定。
- 默认策略必须能够复现引入策略层之前已经批准的基线行为。
- 如果策略矩阵本身暴露明显过拟合，应再锁定一批未参与策略调试的输入，验证策略差异不会破坏此前 G 系列建立的泛化能力。

## 6. G 系列：泛化验证方法与进度

G 系列不继续为每个问题写一个新剧情，而是把同一算法放入连续、确定性且未逐点调试的输入范围中。

每个 G 增量遵循统一节奏：

1. 一次只验证一个泛化假设或一个输入轴。
2. 后台运行一组确定性样本，页面只展示少量边界代表回放。
3. 不允许读取场景 ID、预设结果或为单个参数点增加补丁。
4. 自动检查确定性、信息边界、角色所有权、合法球权与路径、因果顺序和无远程掩护。
5. 先交给用户亲眼判断运动语言与决策节奏。
6. 用户确认后，每个成功增量单独 commit 并 push。
7. 如果审计失败，停止扩范围，先记录最小失败区间；修复必须改善一类输入，而不是一个样本点。

泛化并不要求所有相邻输入产生相同结果。真正要求的是：变化连续、边界稳定、差异可由公开几何或时间解释，并且边界附近不逐帧抖动。
