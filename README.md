# 2v2 挡拆算法最小闭环

一个独立、确定性的右侧 2v2 挡拆原型。只验证：

- O5 在 O1 右侧设掩护，O1 根据 D1 的公开起手站位使用或拒绝；
- 换防后比较 O1 攻击 D5 与 O5 卡住 D1；另保留 D1 走掩护下方，以及 O1 拒绝后 D5 协防、O5 顺下接应；
- 进攻队级规划器、防守队级规划器、中立世界解析器三层分离；
- 固定 1/60s 世界步长，事件/看门狗触发重规划，计划带最短承诺与滞回；
- contact、route_exposure、impeded、screen_effective、越肩、换防、走下方、卡位、过髋、拒绝协防、三类传球窗、球的飞行/先触球与处理窗口分开解析；
- 场景目录、播放、暂停、重置、重放，以及计划、角色、事件、候选与否决可视化。

## 运行

需要 Node.js >=22.13.0。

~~~bash
npm install
npm run dev
~~~

打开终端显示的本地地址。核心检查：

~~~bash
npm test
~~~

完整构建检查：

~~~bash
npm run build
~~~

## 最短架构说明

- lib/pnr-core.ts：双方队级规划、确定性短推演、中立运动/几何/球权/事件解析。
- lib/pnr-scenarios.ts：网页场景目录。每个批准局面只追加一条带稳定 ID 的公开输入预设；观察说明与回归检查点不会传入模拟内核。
- lib/pnr-generalization.ts：G01 只读审计探针；用同一现有内核扫描速度输入、复跑逐 tick 轨迹并汇总边界，不修改候选或评分。
- components/PnrLab.tsx：可丢弃的 Canvas 观察入口，不参与任何球队决策。
- tests/pnr-core.test.mjs：确定性、信息边界、角色所有权、合法路径/球权、固定因果顺序、无远程掩护，S01–S08 关键篮球门控，以及 G01 边界与逐 tick 双运行复现。

两队规划器只接收公开坐标、速度、球权、已解析事实和自队名单；观察对象不含对方计划。中立解析器只执行运动、碰撞、边界、传球飞行、先触球与事实归属；它不对候选评分，也不替球队选择方案或接球结果。

## G01 · O1 速度决策边界泛化探针

G01 不属于 S01–S08 场景目录，也不向模拟内核增加方案或分支。它固定 `neutral`、seed 17、D1 绕前反应 0.12s、接球后恢复 0、`pnr_resolution` 停止范围，只把 O1 最高速度从 3.72m/s 扫到 4.08m/s，步长 0.02，共 19 个输入。每个输入从初始状态运行两次，并比较每一 tick 的世界哈希、双方计划、角色、事件和候选记录。

当前未调参审计结果：3.72–3.98m/s 连续选择 `FEED_SEAL`，4.00–4.08m/s 连续选择 `ATTACK_BIG`；所有样本均在换防完成可消费后的 tick 145 作出第一次进攻重规划，两次逐 tick 复现一致，没有 `FEED→ATTACK→FEED` 回跳。网页 G01 标签提供 4.08m/s 稳定高侧、3.98m/s 最后 FEED 和 4.00m/s 首个 ATTACK 三个回放。

## 明示假设与停止点

- 半场坐标近似米制，不拟合真实球员生物力学。
- S01/S03/S04/S05 使用同一中性跟防起手；S02 改变 D1 的公开踩右站位。S06 只把 O1 公开最高速度从 3.72m/s 提到 4.08m/s；S07 使用公开的下方起手深度；S08 使用更强的踩右站位。
- 使用掩护时，O1 沿 O5 身外的离散贴肩弧线通过；越肩后 O5 才顺下，防守执行 D1→O5、D5→O1 的原子换防。
- 换防完成后，3.72m/s 基线短推演在“攻击 D5 / 喂 O5 卡位 / 拉出重置”中选择喂 O5；G01 显示现有评分随 O1 速度在 3.98–4.00m/s 之间连续翻转到攻击 D5。
- O5 卡位与传球净空公开成立后，防守规划器比较合法绕前 ETA 与预计高吊到达时间。S01 约为 0.19s 对 0.21s，选择绕前并由 D1 先触球；S03 含 0.12s 反应成本，约为 0.31s 对 0.21s，绕前被硬否决，D1 留在身后，O5 先触球。
- S04 与 S03 在 O5 接球前逐帧一致。接球事件到下一决策边界才触发双方新方案：进攻选择 O5 转身而非分回 O1；防守选择 D5 留守 O1 而非下沉，O1 外移、D1 从身后追防。
- S05 与 S04 在 O5 接球前逐帧一致，并明示加入 0.36 秒 D1 接球后恢复成本。防守先选择 D5 下沉；只有 D5 实际进入 O5 的 1.12m 局部半径且离开 O1 至少 1.28m 后，进攻才允许改选分球。O1 随后漂向右侧出口，真实回传走廊成立后 O5 出球。
- S06 在同一换防完成事件后由短推演改选 `ATTACK_BIG`。O1 先攻击 D5 外侧髋部，取得横向优势后才转向篮筐；O5 清空、D1 留守 O5、D5 后撤遏制，约 4.17 秒止于近筐过髋窗口。
- S07 中 D1 从 O5 与篮筐之间的合法通道走下方，D5 短收但保持 O5 责任；不发生换防。O1 在 D1 追回前约 3.23 秒得到中距离处理窗口，不解析出手。
- S08 先由更强踩右的公开横向落后触发协防资格；D1 真正落后后，D5 绕过 O5 肩位进入 O1 的局部突破线。O1 看到协防后才收住并改选顺下分球，O5 约 2.97 秒合法接球。
- 拒绝掩护本身不触发换防；S02 中 D5 继续留守 O5，S08 只有在 D1 落后与 D5 局部移动都公开成立后才协防。
- 高吊球以 9.2m/s、S05 回传以 13.6m/s、S08 顺下分球以 11.4m/s 走完整二维路径；飞行期间球权为空，防守仍按局部触球顺序破坏。
- S01–S03 止于第一段结果；S04 止于 O5 近筐处理窗口；S05 止于 O1 接回传；S06–S08 分别止于过髋、急停和顺下接球窗口。均不模拟出手、进球、犯规、转换、更多人数或 5v5。
- 视觉壳用于亲眼判断运动语言与决策节奏，不是生产 UI。
