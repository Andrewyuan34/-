# 2v2 挡拆算法最小闭环

一个独立、确定性的右侧 2v2 挡拆原型。只验证：

- O5 在 O1 右侧设掩护，O1 根据 D1 的公开起手站位使用或拒绝；
- 换防后进攻比较 O1 攻击 D5 与 O5 卡住 D1；防守独立比较遏制持球与 D1 抢传球侧；
- 进攻队级规划器、防守队级规划器、中立世界解析器三层分离；
- 固定 1/60s 世界步长，事件/看门狗触发重规划，计划带最短承诺与滞回；
- contact、route_exposure、impeded、screen_effective、越肩、换防、卡位、传球窗、球的飞行/先触球与错位结果分开解析；
- 播放、暂停、重置、重放，以及计划、角色、事件、候选与否决可视化。

## 运行

需要 Node.js >=22.13.0。

~~~bash
npm install
npm run dev
~~~

打开终端显示的本地地址。核心检查：

~~~bash
npm test
~~~

完整构建检查：

~~~bash
npm run build
~~~

## 最短架构说明

- lib/pnr-core.ts：双方队级规划、确定性短推演、中立运动/几何/球权/事件解析。
- components/PnrLab.tsx：可丢弃的 Canvas 观察入口，不参与任何球队决策。
- tests/pnr-core.test.mjs：确定性、信息边界、角色所有权、队友净空、原子换防、卡位/绕前边界、传球飞行与合法球权、事件因果顺序、无远程掩护。

两队规划器只接收公开坐标、速度、球权、已解析事实和自队名单；观察对象不含对方计划。中立解析器只执行运动、碰撞、边界、传球飞行、先触球与事实归属；它不对候选评分，也不替球队选择方案或接球结果。

## 明示假设与停止点

- 半场坐标近似米制，不拟合真实球员生物力学。
- “中性跟防 / 提前踩右侧”只改变 D1 的公开起手站位，仍是同一个右侧挡拆场景。
- 使用掩护时，O1 沿 O5 身外的离散贴肩弧线通过；越肩后 O5 才顺下，防守执行 D1→O5、D5→O1 的原子换防。
- 换防完成后，当前确定性短推演在“攻击 D5 / 喂 O5 卡位 / 拉出重置”中选择喂 O5：O1 横移制造角度，O5 顺下压住 D1。
- O5 卡位与传球净空公开成立后，D1 的防守规划器改选抢传球侧；O1 随后传出高吊球。当前中性输入稳定在 3.18 秒结束为 D1 先触球并取得球权。
- 拒绝掩护时不换防，D1 保持 O1、D5 保持 O5。
- 高吊球以 9.2m/s 固定速度走完整平面路径，飞行期间球权为空；它可越过近身 D5，但 D1 仍按局部触球顺序破坏。这是替代真实球高的最小可换假设。
- 本闭环止于 O5 接球、传球被破坏、O1 错位结果或拒绝后的突破判断点；不模拟投篮、犯规、丢球后转换、更多战术或 5v5。
- 视觉壳用于亲眼判断运动语言与决策节奏，不是生产 UI。
