# 篮球战术空间推演器

一个可解释、可重放、可批量运行、可被 AI 安全扩展的二维篮球战术空间推演器。

项目目前处于 M0“规格与边界”阶段。当前交付重点是先把产品问题、明确非目标、运行时模型、数据契约、AI 边界和验收标准定义清楚，再开始实现。

## 它是什么

- 二维俯视半场；
- 使用圆点表示球员；
- 同时推演进攻战术与防守战术；
- 支持单点动作、局部配合和整体协作；
- 由当前站位、角色、战术目标和空间关系动态选择动作；
- 能解释每次选择，并使用相同种子确定性重放；
- 未来允许 AI 创建、解释和校准战术，但核心模拟不依赖 AI。

## 它不是什么

- 不是完整篮球比赛模拟器；
- 不是篮球游戏；
- 不是固定路线战术动画播放器；
- 不是人体或篮球物理引擎；
- 不模拟比分、比赛时间、进攻时间、犯规、疲劳、伤病和换人；
- 不保存球员速度、朝向或身体姿态；
- 不模拟投篮命中和真实比赛胜负；
- 不让大语言模型逐步控制球员；
- 不对真实比赛结果作确定性预测。

## 核心设计

系统采用以下闭环：

    球员位置与球权
      → 派生空间事实
      → 战术目标与角色约束
      → 生成候选动作
      → 合法性过滤与评分
      → 双方协调并执行
      → 结构化事件与决策轨迹
      → 新的球员位置与球权

战术描述“目标、约束和允许动作”，而不是完整时间轴。球员动作使用可组合的动作原语，并在掩护就位、防守换防、传球线路打开或动作失效等事件发生时重新规划。

系统不使用比赛时间，但保留内部逻辑步，以表达“谁先到位、什么事件先发生”。逻辑步不等于现实秒数，也不要求球员速度状态。

## 技术方向

- TypeScript 严格模式；
- 无头、确定性、事件驱动的模拟内核；
- React + Vite 的 Web 应用；
- SVG 球场和圆点可视化；
- JSON Schema Draft 2020-12 作为战术和 AI 输出的权威契约；
- 启发式与效用策略作为首个可解释基线；
- AI 通过独立适配器接入，核心包不依赖模型或网络。

选择 Web 技术而非游戏引擎，是因为当前问题只有少量二维对象，重点是空间逻辑、解释、重放和批量推演，不是 3D、动画和物理。

## 首个可验证闭环

第一阶段业务场景是半场 2v2 挡拆：

- 进攻：移动、设置掩护、使用或拒绝掩护、顺下、外弹、传球；
- 防守：跟防、绕掩护、换防、协防、回位；
- 同一战术在防守站位变化后必须产生可解释的候选、评分或选择变化；
- 不模拟投篮是否命中。

## 计划里程碑

| 里程碑 | 结果 |
| --- | --- |
| M0 | 产品、非目标、架构、AI 边界和验收规格 |
| M1 | 确定性空间内核、事件、重放和基础 SVG 球场 |
| M2 | 动作原语、策略接口、决策轨迹和无头运行 |
| M3 | 可交互、可解释的 2v2 挡拆攻防闭环 |
| M4 | 3v3 弱侧空间、协防和轮转 |
| M5 | 战术编辑器与受校验的 AI 辅助 |
| M6 | 5v5 扩展与外部数据校准接口 |

项目目前停留在 M0。只有用户明确要求开始实现时才进入 M1；规格整理本身不构成开发授权。
