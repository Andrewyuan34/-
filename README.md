# 2v2 挡拆算法最小闭环

一个独立、确定性的 2v2 挡拆原型。以右侧为规范战术坐标，并用真实左侧世界验证左右镜像。只验证：

- O5 在 O1 右侧设掩护，O1 根据 D1 的公开起手站位使用或拒绝；
- 换防后比较 O1 攻击 D5 与 O5 卡住 D1；另保留 D1 走掩护下方，以及 O1 拒绝后 D5 协防、O5 顺下接应；
- 进攻队级规划器、防守队级规划器、中立世界解析器三层分离；
- 固定 1/60s 世界步长，事件/看门狗触发重规划，计划带最短承诺与滞回；
- contact、route_exposure、impeded、screen_effective、越肩、换防、走下方、卡位、过髋、拒绝协防、三类传球窗、球的飞行/先触球与处理窗口分开解析；
- 场景目录、播放、暂停、重置、重放，以及计划、角色、事件、候选与否决可视化。

## 运行

需要 Node.js >=22.13.0。

~~~bash
npm install
npm run dev
~~~

打开终端显示的本地地址。核心检查：

~~~bash
npm test
~~~

完整构建检查：

~~~bash
npm run build
~~~

## 最短架构说明

- lib/pnr-core.ts：双方队级规划、确定性短推演、中立运动/几何/球权/事件解析，以及显式四人初始位置的验证、深拷贝与世界创建。
- lib/pnr-scenarios.ts：网页场景目录与旧 cue 到公开初始坐标的唯一适配层。每个批准局面只追加一条带稳定 ID 的公开输入预设；cue、观察说明与回归检查点不会传入模拟内核。
- lib/pnr-generalization.ts：G01 只读审计探针；用同一现有内核扫描速度输入、复跑逐 tick 轨迹并汇总边界，不修改候选或评分。
- lib/pnr-g02-generalization.ts：G02 只读审计探针；扫描 D1 绕前反应成本，并把预计 ETA、方案可行性与后续真实球路触球分别记录。
- lib/pnr-g03-generalization.ts：G03 只读审计探针；扫描 D1 接球后恢复成本，并把防守意图、D5 真实局部协防、O5 观察后分球分别记录。
- lib/pnr-g05-spatial-generalization.ts：G05 只读空间审计；保留 33 个候选位置账本，对 31 个合法输入执行双运行，并把 2 个初始重叠输入记录为 G04 预期拒绝。
- lib/pnr-g06-combinations.ts：G06 只读组合审计；组合已经通过单轴门的速度、绕前/恢复时间和三个合法位置，共运行 21 个确定性输入。
- lib/pnr-g07-mirroring.ts：G07 镜像审计；让 S01–S08 与全部 G06 输入分别在真实 right/left 世界运行，并逐 tick 对比位置、速度、球路、计划、候选、角色和事件。
- components/PnrLab.tsx：可丢弃的 Canvas 观察入口，不参与任何球队决策。
- tests/pnr-core.test.mjs：确定性、信息边界、角色所有权、合法路径/球权、固定因果顺序、无远程掩护，S01–S08 关键篮球门控，G01–G03 边界，G04 输入契约，G05 的 33=31+2 空间审计，G06 组合因果门，以及 G07 右侧零变化与左右镜像门。

两队规划器只接收公开坐标、速度、球权、已解析事实和自队名单；观察对象不含对方计划。中立解析器只执行运动、碰撞、边界、传球飞行、先触球与事实归属；它不对候选评分，也不替球队选择方案或接球结果。

## G01 · O1 速度决策边界泛化探针

G01 不属于 S01–S08 场景目录，也不向模拟内核增加方案或分支。它固定 `neutral`、seed 17、D1 绕前反应 0.12s、接球后恢复 0、`pnr_resolution` 停止范围，只把 O1 最高速度从 3.72m/s 扫到 4.08m/s，步长 0.02，共 19 个输入。每个输入从初始状态运行两次，并比较每一 tick 的世界哈希、双方计划、角色、事件和候选记录。

当前未调参审计结果：3.72–3.98m/s 连续选择 `FEED_SEAL`，4.00–4.08m/s 连续选择 `ATTACK_BIG`；所有样本均在换防完成可消费后的 tick 145 作出第一次进攻重规划，两次逐 tick 复现一致，没有 `FEED→ATTACK→FEED` 回跳。网页 G01 标签提供 4.08m/s 稳定高侧、3.98m/s 最后 FEED 和 4.00m/s 首个 ATTACK 三个回放。

## G02 · D1 绕前反应时间边界泛化探针

G02 同样不属于场景目录，也不修改现有防守候选或触球解析。它固定 `neutral`、seed 17、O1 最高速度 3.72m/s、接球后恢复 0 与 `pnr_resolution`，只把 D1 绕前反应成本从 0.00s 扫到 0.16s，步长 0.01，共 17 个输入。每个输入运行两次，并逐 tick 比较世界、计划、角色、事件和候选记录。

当前未调参结果：0.00–0.01s 连续选择 `FRONT_SEAL`，D1 在完整高吊球路上真实先触球；0.02–0.16s 连续选择 `BACKSIDE_CONTEST`，O5 走完球路后合法接球。0.01s 时绕前 ETA 0.199s / 高吊 ETA 0.210s；0.02s 时为 0.209s / 0.210s。现有可行性公式还要求 0.004s 到位余量，因此第二个样本被否决；这条余量来自原算法，不是 G02 新增阈值。所有样本在 tick 180 作第一次绕前重规划、tick 181 出球；D1 破坏发生于 tick 191，O5 接球发生于 tick 192。17/17 双运行一致，没有“破坏→接球→再次破坏”回跳。

网页 G02 标签提供 0.01s 最后破坏、0.02s 首次接球和 0.12s 原始 S03 稳定接球三个回放；预计 ETA 只约束防守计划，最终触球者仍由中立解析器逐 tick 检查实际球段与局部身体半径。

## G03 · D1 接球后恢复时间边界泛化探针

G03 固定 `neutral`、seed 17、O1 最高速度 3.72m/s、D1 绕前反应 0.12s，只把 D1 在 O5 接球后的恢复成本从 0.00s 扫到 0.60s，步长 0.03，共 21 个输入。所有输入使用同一个中立 `post_catch_resolution` 观察终止条件：首次形成终结窗口或完成回传接球时冻结；这个 horizon 不会进入任一队规划器观察。每个输入运行两次，逐 tick 比较世界、双方计划、四人角色、事件和候选记录。

当前未调参结果：0.00–0.18s 连续选择 `STAY_HOME_POST`，D5 留守 O1，O5 在 tick 228 形成近筐处理窗口；0.21–0.60s 连续选择 `DIG_POST`。所有样本在 tick 192 由 O5 接球、tick 193 完成第一次接球后重规划。高侧样本虽然在 tick 193 已决定下沉，进攻仍先保持 `POST_FINISH`；D5 到 tick 231 才真实满足 D5–O5 ≤1.12m 且 D5–O1 ≥1.28m，O5 在该公开事件可消费后的 tick 232 才首次选择 `KICK_OUT`，随后 tick 260 出球、tick 273 由 O1 合法接回传。21/21 双运行一致，只有 0.18–0.21s 一次边界转换，没有回跳；当前离散扫描没有“已决定 DIG、但尚未来得及形成真实帮助”的最终过渡样本，但审计记录仍将三层分别保存。

网页 G03 标签提供 0.18s 最后留守、0.21s 首次下沉和 0.36s 原始 S05 三个回放。页面分别展示防守是否决定下沉、D5 是否真实到位、O5 是否在观察后改选分球，并列出接球后的每次进攻重规划与候选否决。

## G04 · 显式初始位置契约

模拟内核现在要求公开、完整的 `initialPositions = { O1, O5, D1, D5 }`。四个坐标必须为有限数值、球员完整身体必须位于场内、任意两人不得初始重叠；缺失或非法输入会给出明确错误，不做 clamp，也不恢复默认坐标。构造器深拷贝输入，初始球权仍归 O1，球的位置等于显式 O1 坐标，状态哈希包含四人的实际起手位置。

`neutral`、`overplay_right`、`under_gap` 等 cue 已从模拟配置和核心源码移除，只在 `pnr-scenarios.ts` 将旧场景适配成显式坐标。S01–S08 与 G01–G03 均通过同一位置接口创建。重构前后逐 tick 公开位置、球、双方计划、角色、候选、事件和终止结果的行为摘要完全一致；总状态哈希允许因配置元数据格式改变。

## G05 · 小范围确定性位置扰动

G05 保留原始 33 个稳定候选 ID：baseline 1 个，加 O1/O5/D1/D5 的 x/y 八条坐标轴各四个非零偏移（±0.12m、±0.24m）。审计口径是 `33 candidates = 31 simulated + 2 expected rejected`。`O1.y/-0.24` 与 `D1.y/+0.24` 会令 O1/D1 初始中心距降到 0.599m，小于 0.680m 合法下限，因此继续由 G04 在创建世界前明确拒绝；两点保留在账本中，不静默跳过、不 clamp，也没有动画入口。

其余 31 个合法输入各完整运行两次。当前未调参结果为 31/31 逐 tick 世界、双方计划、角色和事件一致；没有越界、非法球权、身体穿越、角色冲突、远程阻挡、非法 impeded、因果乱序、看门狗重规划或无解释卡死。所有样本当前都从 `USE_RIGHT_SCREEN / SWITCH_READY` 开始，形成 use 分支并终止于 O5 合法接球的 `seal_catch_advantage`，终止 tick 为 185–198。相同有序坐标轴内没有 plan/branch 的 A→B→A 回跳；结果不变并非预设通过条件，而是本次扫描的实际审计事实。

网页 `G04–G05 · 空间探针` 显示完整 33 行账本、当前四人第一帧坐标、baseline 对比、候选分数/可行性/否决、四层掩护事实和核心检查。只提供三个合法代表回放：baseline、终止时机变化最大的 O5 极值 `O5.x/-0.24`，以及初始 USE/REJECT 分差最小的 D1 样本 `D1.x/+0.24`。本轮没有发现结果边界，因此没有人为凑第四个动画。

## G06 · 有限参数交叉组合

G06 不增加候选、PlanId、评分权重或篮球行为。Matrix A 组合 G01 的 3.98/4.00m/s 边界、G02 的 0.01/0.02s 边界与 baseline、`O5.x/-0.24`、`D1.x/+0.24` 三个位置，共 12 个输入；Matrix B 固定 3.72m/s 与 0.12s 绕前反应，组合 G03 的 0.18/0.21/0.36s 恢复值与相同三个位置，共 9 个输入。

21/21 输入均完整运行两次并逐 tick 复现。未进入对应阶段的参数不改变此前共同前缀；`ATTACK_BIG` 未发起高吊时，绕前反应不改变球的结果；O5 接球前，接球后恢复值不改变此前计划或运动。组合后的不同结果都保留候选分数、可行性和真实几何证据。网页 `G06 · 参数交叉` 提供真实破坏、攻击换防大个、位置改变接球后判断三个代表回放。

## G07 · 左右镜像与相对战术坐标

公开配置增加 `screenSide: "right" | "left"`。规划器先把公开世界映射到以右侧为规范的战术坐标，共享原有候选、评分、阈值、角色和事件逻辑，再把运动意图映射回真实世界坐标；中立解析器仍只在真实世界中处理运动、碰撞、传球与触球。没有 left planner、left threshold 或左侧 PlanId。

战术坐标引入后，S01–S08、G01–G05 和 G06 的既有右侧行为门保持不变。镜像审计覆盖 S01–S08 8 对和 G06 21 对；每一对的 right/left 各运行两次。29/29 对的四人位置与速度、球的位置/速度/传球目标、运动目标、候选分数与证据、计划、角色、事件 tick 和终止原因均互为镜像或保持标量相等，最大数值误差约 `7.39e-14m`，低于明确的 `1e-9m` 容差。网页 `G07 · 左右镜像` 播放的是真实左侧世界，不镜像 Canvas；side 在 tick 0 可切换，开始运行后锁定。

## G08 · 锁定 held-out 泛化检查点

G08 先把篮球核心冻结在 `d92ed9f63bba3dcfa28d65d54b6a47c7e3e1f74c`，再以独立 seed `20260808` 生成并锁定 24 个只含公开输入的 manifest（12 right + 12 left）。manifest commit 为 `b994d2d7520f00069e011e629ccb54f90ba8c5d5`，内容哈希为 `sha256:5ff19401f264663f5d5fcfc2e944cb1e0ef4430093a11281193f7f8d8d07fee3`。生成器只做有限值、场地边界、初始身体重叠和重复输入检查，不运行模拟、规划器、评分或终止解析来筛选样本。

`lib/pnr-g08-heldout-manifest.ts` 保存冻结输入契约；`lib/pnr-g08-heldout-audit.ts` 让全部输入在同一个 `post_catch_resolution` 观察范围内各运行两次，记录候选、计划、角色、事件、球路、局部触球、身体净空、承诺期与不变量。首次揭示结果为 24/24 逐 tick 确定复现，信息边界和核心不变量全部通过；结果分布为 1 个防守遏制、3 个持球人优势、4 个内线处理窗口和 16 个分球接回。没有由时间上限形成的 `defense_contained`；唯一防守结果由真实 `switch_contained` 事件结束。

网页 `G08 · held-out 检查点` 显示冻结 commit、manifest seed/hash、完整 24 行审计摘要，并在审计结束后按公开统计自动选择四个回放：最接近候选边界、位置扰动最大、重规划最多/运行最长，以及不同侧或结果类别。当前停在用户亲眼验收点；未经确认不提交 G08 审计/UI，也不开始 P00。

## 明示假设与停止点

- 半场坐标近似米制，不拟合真实球员生物力学。
- S01/S03/S04/S05 使用同一中性跟防起手；S02 改变 D1 的公开踩右站位。S06 只把 O1 公开最高速度从 3.72m/s 提到 4.08m/s；S07 使用公开的下方起手深度；S08 使用更强的踩右站位。
- 使用掩护时，O1 沿 O5 身外的离散贴肩弧线通过；越肩后 O5 才顺下，防守执行 D1→O5、D5→O1 的原子换防。
- 换防完成后，3.72m/s 基线短推演在“攻击 D5 / 喂 O5 卡位 / 拉出重置”中选择喂 O5；G01 显示现有评分随 O1 速度在 3.98–4.00m/s 之间连续翻转到攻击 D5。
- O5 卡位与传球净空公开成立后，防守规划器比较合法绕前 ETA 与预计高吊到达时间。S01 约为 0.19s 对 0.21s，选择绕前并由 D1 先触球；S03 含 0.12s 反应成本，约为 0.31s 对 0.21s，绕前被硬否决，D1 留在身后，O5 先触球。
- S04 与 S03 在 O5 接球前逐帧一致。接球事件到下一决策边界才触发双方新方案：进攻选择 O5 转身而非分回 O1；防守选择 D5 留守 O1 而非下沉，O1 外移、D1 从身后追防。
- S05 与 S04 在 O5 接球前逐帧一致，并明示加入 0.36 秒 D1 接球后恢复成本。防守先选择 D5 下沉；只有 D5 实际进入 O5 的 1.12m 局部半径且离开 O1 至少 1.28m 后，进攻才允许改选分球。O1 随后漂向右侧出口，真实回传走廊成立后 O5 出球。
- G03 表明同一接球前缀下，现有防守评分在 0.18–0.21 秒恢复成本之间从留守连续翻转为下沉；选择 `DIG_POST` 本身不等于协防已经成立，也不会直接开放 `KICK_OUT`。
- S06 在同一换防完成事件后由短推演改选 `ATTACK_BIG`。O1 先攻击 D5 外侧髋部，取得横向优势后才转向篮筐；O5 清空、D1 留守 O5、D5 后撤遏制，约 4.17 秒止于近筐过髋窗口。
- S07 中 D1 从 O5 与篮筐之间的合法通道走下方，D5 短收但保持 O5 责任；不发生换防。O1 在 D1 追回前约 3.23 秒得到中距离处理窗口，不解析出手。
- S08 先由更强踩右的公开横向落后触发协防资格；D1 真正落后后，D5 绕过 O5 肩位进入 O1 的局部突破线。O1 看到协防后才收住并改选顺下分球，O5 约 2.97 秒合法接球。
- 拒绝掩护本身不触发换防；S02 中 D5 继续留守 O5，S08 只有在 D1 落后与 D5 局部移动都公开成立后才协防。
- 高吊球以 9.2m/s、S05 回传以 13.6m/s、S08 顺下分球以 11.4m/s 走完整二维路径；飞行期间球权为空，防守仍按局部触球顺序破坏。
- S01–S03 止于第一段结果；S04 止于 O5 近筐处理窗口；S05 止于 O1 接回传；S06–S08 分别止于过髋、急停和顺下接球窗口。均不模拟出手、进球、犯规、转换、更多人数或 5v5。
- 视觉壳用于亲眼判断运动语言与决策节奏，不是生产 UI。
